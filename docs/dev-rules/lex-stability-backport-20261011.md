## Lex 适配

- Orca MCP 与 OMP 共用同一个 20 工具清单；新增插话和排序通过现有宿主授权与队列
  准入边界。Worker 的 OMP host-tool 与 MCP 共用 send-to-lead 实现，保留回报结算。
- 保留 OMP 仅统计最终工具结果的规则，流式片段不计入循环；新增复核测试覆盖 OMP。
- 保留 Lex 的 shared-task scope、同账号物理宿主路由、账号代际与偏好损坏恢复。
- 未声明档位增加准入标记，同时保留 Lex 已有的自定义 Claude/Codex 默认选择档位；
  显式能力优先，Pi 维持上游明确的例外。
- 模型目录采用 #5400 的最终过滤方案，不保留已被上游撤回的分页协议。
- 更新清单仅调整响应生命周期；Lex 更新源、品牌、发布及签名配置保持原状。
- 伙伴测试文件仅补共享队列接口的 fixture，未改变伙伴生产行为。

## 排除与交付边界

#5470（`282c38885`）修复的是上游新增的手机 Orca Lead/Worker 导航入口。Lex 当前
没有该入口及配套 hook，强行合入会引入额外功能，因此本次排除，未提交孤立 helper。

Android AsyncStorage 64 MiB config plugin 与 iOS UITextView 原生补丁会改变 runtime
fingerprint，必须随新安装包发布，不能只推 OTA。无数据库 schema/migration 变更。
原生变更合并仍需对应把关人确认；本任务不合并、不发版。

按用户要求不在本地重跑测试、typecheck 或打包，交由 PR CI 验证。源码检查仅覆盖
冲突标记、JSON/TypeScript 语法、新增相对 import、diff 与 DCO；不代表运行验证通过。
未调用真实模型、账号或设备，未验证实机 Light/Dark、Android/iOS 原生行为。
