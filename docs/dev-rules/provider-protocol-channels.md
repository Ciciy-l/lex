# 供应商协议渠道

供应商配置以协议组织，协议下可有多个具名渠道，每个渠道协议项保存自己的 URL、模型与凭证。
同一渠道可以显式加入多个协议；URL 相同或模型同名不构成合并凭证的依据。

## 身份与选择

- supplier ID 是设置与存储身份；channel ID 是一份可选连接的稳定身份，改名不改 ID。
- 自动协议使用 channel ID 作为已有 `providerId`；固定协议使用
  `channelId--protocol`。任务、默认选择、收藏和跨端切换沿用现有完整 provider/model/engine
  事务。旧端不会忽略一个新字段后把固定协议误解成自动。
- 同一供应商、同一模型的普通列表只显示一行，展开选择渠道和协议。分组只影响展示；
  模型窗口、价格、推理和 Fast 能力均来自实际所选连接，禁止取多个渠道能力的并集。
- 自动协议在所选渠道内优先引擎原生协议。固定协议、已删除渠道和缺失模型不回落别的
  渠道或默认账号。缺少某个协议的凭证只影响该协议解析出的模型，不冻结整个供应商。

Claude Code 原生使用 Anthropic Messages，Codex 原生使用 Responses。它们使用其他
协议时经过 Lex 宿主桥接，不能标作引擎原生支持。Pi 和 OMP 的 Google Gemini
使用原生 Google payload；Google Cloud 上的 Claude 不是 Gemini 协议。
共享模型协议标识和默认启用推导与 OMP 的四个实际协议入口一致；缺少路由仍为未知，
模型原生 API 与所选 wire 不一致仍标兼容，用户显式关闭保持关闭。

## 存储与迁移

`custom_providers.channels` 是版本化 JSON，Drizzle migration 为
`0117_provider_protocol_channels.sql`。密钥和全部自定义请求头仍只存 Main 的账号隔离
safeStorage，以 `(channelId, protocol-<protocol>)` 分槽；JSON 和远端目录不含明文凭证。

旧配置先复制加密凭证，再以 CAS 发布渠道。不同凭证或连接配置不合并，旧密钥保留，
`legacyBindings` 为旧任务和旧收藏保留原引擎/协议身份。Pi 未声明协议时仍按旧 Chat
默认值迁移。密文不可读、迁移中断或账号代次变化不能破坏原配置。损坏的新 JSON 保留
可修复条目，路由关闭，不用旧 runtimes 静默恢复。

旧别名跟随原渠道同协议的显式编辑；删掉的模型/协议不转绑。用户显式隐藏/停用偏好
通过原 ID 别名继承。OAuth、订阅、Vertex、Bedrock 等专用配置不强制转换成 URL/Key，
保留原有创建和登录入口。普通预设保留协议、模型元数据及请求头。
旧模型元数据、上下文上限和价格覆盖仅在原引擎、原渠道、原模型和原协议仍一致时继承；
上下文和价格编辑/恢复默认使用同一旧键，保持旧任务与新入口一致。改选另一协议或
另一渠道后不继承该键，报价仍归属实际所选渠道。
组级停用偏好的恢复默认使用供应商身份，直接删除 override；目录不可读或来源已下架
不应阻止删除陈旧偏好。单模型停用仍按当前精确渠道校验后归属供应商保存。

配置和凭证写入在账号绑定的全局存储队列内完成，失败补偿；请求路由在发布窗口关闭。
canonical 表单带 Main 发出的 `readRevision`，旧窗口及异步发现的迟到保存必须拒绝。
端点变化未明确提供新密钥/请求头时清除旧凭证，不把旧钥匙带往新地址。
渠道表单使用同步请求锁，保存或发现期间不重复提交、不关闭；失败后恢复编辑。
首次打开聚焦供应商名称，空闲时支持取消、Esc 和遮罩关闭；未保存时先确认。

添加供应商沿用最大 600px 的紧凑单列表单，顶部用「按协议 / 按 Harness」Tab 切换，
不再使用专用供应商大按钮。按协议表单把四种 wire protocol 作为快速切换的 Tab；
每个协议内使用具名渠道卡片选择当前连接，并显示已关联协议和该协议的模型数量。
没有当前协议项的已有渠道以单独的附加动作呈现。窄窗仍用同一表单并回到单栏，
标题、两层 Tab 和底部动作固定，中间独立滚动。添加新渠道与给已有渠道增加协议
是不同动作。同名模型不合并连接身份；测试连接/发现模型只校验当前协议项，保存
整份配置时定位首个错误。切换预设和关闭未保存草稿需确认；协议 Tab 往返保留各自
草稿和未提交的模型 ID，切换后焦点留在所选 Tab，可连续用方向键切换；隐藏表单
不监听 Esc、不抢焦点。编辑已有配置沿用其原有表单。连接字段或模型 ID 编辑后旧
测试结果失效。
模型 ID 逐条显示与编辑；可粘贴按换行分隔的多个 ID。持久化仍使用原有字符串数组，
按换行 trim、过滤空项、精确去重并保持首次出现顺序；逗号是合法 ID 字符，不是分隔符。
新增行须先按 Enter 或点「添加」提交；存在未提交行时保存、测试连接和发现模型都被阻止
并提示，避免草稿被静默丢弃。整理既有 ID 只按精确 ID 复用原模型对象，保留其名称、
上下文、价格、路由和启用状态；新增 ID 才取默认值。多行粘贴与输入框现有内容和光标
位置合并；单行粘贴中的逗号按合法 ID 字符处理，不拆分。

同名渠道以可访问的实例序号（如 1/2）区分，身份仍按稳定 channel id。已保存端点下
修改模型 ID 时，Main 在核验可信 sender、owner/generation、账号边界和供应商 mutation
屏障后，可按已保存端点复用该协议的已存密钥与 Main-only headers 测试草稿模型；端点或
协议变化、账号边界 pending、供应商正在 mutation 时一律 fail closed 并提示用户保存或
填写新密钥，不发送探测，也不回填 Renderer。端点变化必须重新填写密钥或请求头，旧凭证
不得跟随新端点。连接测试不跟随任何重定向（包括同源跳转）：3xx 以 `REDIRECT_BLOCKED`
失败并提示填写最终端点，避免把已存密钥或自定义认证头重放到第二来源；探测结果只向
Renderer 返回 code/status/latency 等安全摘要，不返回上游原文。原生 SDK 探测同样禁止
跟随重定向：可注入 fetch 的适配器使用同一 manual 探测；Google Generative AI 走协议
HTTP 探测并校验 generateContent 成功结构（2xx HTML、错误 JSON、空或畸形候选均失败）；
Gemini 的 finishReason 遵循 SDK 语义，仅 STOP/MAX_TOKENS 或缺省成功，其余值（含
SAFETY/BLOCKLIST/RECITATION 及未来失败枚举）返回 `RESPONSE_BLOCKED`；失败原因优先于
文本判定，首候选无 content 的安全阻止也归此类。响应体/SSE 读取与 fetch 共用同一
10s deadline，超时（含 ReadTimeout、嵌套 undici body timeout）返回 `TIMEOUT`，取消
reader 并保留真实 latency，不重置预算；非 deadline 触发的 abort 不冒充超时。
Google Vertex 与 Bedrock 的 SDK 无法把受控 fetch/受信 HTTP 状态带回探测，测试连接以
`PROBE_UNSUPPORTED` 安全拒绝；native 探测以实际响应 status 分类 401/403/429/5xx，
不依赖上游正文重复的 code。

OMP 模型选择使用已连接供应商的真实受管路由与模型目录。原生订阅保留精确账号身份，
OpenAI 通过宿主订阅转发替换进程令牌；普通自定义 runtime 不自动借用其他引擎的凭证。
「按 Harness」表单可从预设补全 OMP 支持的协议，但仍需用户保存连接；不把派生 runtime
写回公共预设或改变快速向导的自动启用范围。已保存 OMP runtime 单独解析相应预设资料。Subagent 模型偏好沿用 OMP
原有的模型 ID 设置，在父任务供应商内校验，不表示独立的跨供应商子任务绑定。

## 跨端和 SSH

Desktop 与 Mobile 共用渠道分组和选择身份。手机沿用原来的 intent/ack 流程，宿主确认
后才显示切换成功；错误、过期回执、断线不改变已确认配置。收藏保留精确 providerId，
编辑收藏与修改运行任务分开。旧主机无 channel 元数据时保留旧界面，不猜造渠道。

收藏的来源身份沿用既有不可变合同；换渠道后可以另存一份收藏，原收藏不被重绑。
收藏编辑页仍调整引擎、思考档和 Fast，不发送旧主机不支持的来源身份更新。

SSH 的 CC/Codex 渠道通过现有 SSH 反向转发连接到宿主协议适配器。每任务独立 loopback
入口和随机 capability；远端不取得真实上游 key。入口只允许相应引擎的 POST 路径，
请求头按白名单转交，私有 capability 在共享适配器消费后删除。账号变化、关闭/解绑、
启动失败和替换同任务入口撤销 capability；路由仍复核所选渠道与模型。
Pi 沿用现有宿主转发。SSH 不新增跨引擎切换，Orca 的引擎与权限范围不扩大。

## 验证边界

0.1.6-rc.1 初版仅有 CI 验证。后续本地验证已覆盖 Windows 隔离开发版的浅色/深色、
窄窗、键盘、保存重开、多渠道、预设和专用表单往返，连接测试使用假 key 与本机 HTTP
服务，经过真实 Main IPC。详见[验收记录](../design-previews/provider-protocol-channels/acceptance.md)。
真实供应商计费请求、SSH 弱网、移动设备触控与实际跨引擎会话切换仍未验收；
本地单测和桌面窄窗不能替代这些场景。
